# Архитектура ассистента разработчика

Ассистент отвечает на вопросы о проекте. Он использует три источника: документацию (RAG),
данные проекта через MCP-сервер и языковую модель.

## Компоненты

- `assistant.py` — точка входа: чат, команды `/help`, `/branch`, `/files`, `/reindex`, режим `--once`.
  Здесь же клиент AITunnel (модель gpt-5.6-luna) и класс `ProjectAssistant`, который собирает контекст.
- `mcp_client.py` — клиент MCP. Запускает `mcp_server.py` как дочерний процесс и говорит с ним по stdio.
- `mcp_server.py` — MCP-сервер проекта. Три инструмента: `git_branch`, `list_files`, `git_diff`.
  Только чтение, пути ограничены папкой проекта.
- `project_docs.py` — сбор документации проекта (README, docs/, схемы и API) и сборка индекса.
- `chunking.py`, `loaders.py`, `embeddings.py`, `index_store.py` — RAG-модули из дней 21–28.
- `local_llm.py` — клиент локальной модели Ollama (вариант `--llm ollama`).

## Поток команды /help

1. Вопрос пользователя.
2. MCP-инструмент `git_branch` — текущая ветка.
3. MCP-инструмент `list_files` — список файлов проекта, без служебных папок.
4. RAG: поиск четырёх самых похожих фрагментов документации в индексе SQLite.
5. Все блоки собираются в один запрос: системная инструкция, вопрос, ветка, файлы, фрагменты.
6. Модель gpt-5.6-luna отвечает по контексту и перечисляет источники в квадратных скобках.

Обычный вопрос без `/help` шагов 2, 3 и 5 с файлами не выполняет: отвечает только по документации.

## Что не делает ассистент

- Не меняет файлы проекта и не выполняет команды git, кроме чтения.
- Не читает исходный код (.py) для ответов: в индекс попадают документация и схемы.
- Не видит файлы, которые ещё не добавлены в git, в `git_diff`. В `list_files` они есть.

## Безопасность

- Ключ AITunnel вводится скрытым вводом или берётся из переменной окружения. В файлы не записывается.
- MCP-сервер отказывает в путях вне папки проекта (например `../`).
- Индекс хранится в папке `output/` рядом с ассистентом.
