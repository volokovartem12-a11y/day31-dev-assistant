# MCP-сервер проекта

MCP (Model Context Protocol) — протокол, по которому ассистент получает данные о проекте.
Здесь сервер и клиент написаны сами на стандартной библиотеке Python, без официального SDK.

## Транспорт

Транспорт stdio. Каждое сообщение — объект JSON-RPC 2.0 на одной строке.
Клиент пишет запросы в stdin сервера, сервер отвечает строкой в stdout.
Сообщение без поля `id` — уведомление, ответа на него нет.

## Методы

- `initialize` — согласование версии протокола (`2024-11-05`) и возможностей сервера.
- `notifications/initialized` — уведомление клиента после `initialize`.
- `ping` — проверка связи.
- `tools/list` — список инструментов с описанием и JSON Schema параметров.
- `tools/call` — вызов инструмента по имени с аргументами.

Ошибки протокола возвращаются полем `error` с кодом: `-32700` (не JSON),
`-32600` (неверный запрос), `-32601` (метод не поддерживается), `-32602` (неверные параметры).

## Инструменты

- `git_branch` — текущая ветка, например `main`. При отсоединённом HEAD возвращает короткий хеш коммита.
- `list_files` — список файлов. Параметр `subdir` ограничивает подпапкой проекта.
- `git_diff` — изменения относительно последнего коммита. Параметр `stat_only` (по умолчанию true)
  возвращает статистику; false — полный diff, обрезанный до 8000 символов.

Ошибка выполнения инструмента (например папка не git-репозиторий) возвращается как обычный результат
с `isError: true`, а сервер продолжает работать.

## Пример обмена

Запрос клиента:

    {"jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": {"name": "git_branch", "arguments": {}}}

Ответ сервера:

    {"jsonrpc": "2.0", "id": 2, "result": {"content": [{"type": "text", "text": "main"}], "isError": false}}

Описание всех инструментов в машиночитаемом виде — в файле `mcp_tools.json`.
