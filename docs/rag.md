# Документация для RAG

Ассистент ищет ответы в документации проекта. Индекс собирается из файлов, которые находит `project_docs.py`.

## Что попадает в индекс

- README и другие файлы верхнего уровня: `README*`, `CONTRIBUTING*`, `CHANGELOG*`, любые `*.md` в корне.
- Всё из папки `docs/`: `.md`, `.txt`, `.sql`, `.json`, `.yaml`, `.yml`, `.graphql`.
- Файлы схем и API в любой папке: все `*.sql`, а также `*.json`, `*.yaml`, `*.yml`, `*.graphql`
  с именем, в котором есть `schema`, `openapi`, `swagger`, `api` или `migration`.

Файлы `.py` в индекс не попадают: ТЗ просит документацию, схемы и API.
Файлы больше 300 КБ пропускаются.

## Как режется текст

Используется стратегия `structure` из дней 21–28:

- Markdown делится по заголовкам. Путь раздела выглядит как «Раздел > Подраздел».
- Остальные файлы делятся по абзацам.
- Фрагмент длиннее 1500 символов делится по абзацам. Фрагмент короче 200 символов склеивается с соседом.

## Эмбеддинги

- `local` (по умолчанию) — хешированный TF-IDF, работает без сети и без ключей. Ищет совпадения слов,
  но не синонимы. Поэтому в документах важно использовать те же термины, что и в вопросах.
- `ollama` — семантические эмбеддинги модели bge-m3 на этом компьютере. Нужна запущенная Ollama.

## Хранение

Индекс — один файл SQLite в папке `output/`. В таблице `chunks` лежат текст фрагмента, путь файла,
раздел и вектор. Схема описана в файле `schema.sql`.

Индекс пересобирается командой `/reindex` в чате или запуском с параметром `--rebuild`.
Пока индекс не пересобран, новые правки документов в ответах не видны.

## Ограничения

- Ассистент отвечает только по тому, что попало в индекс. Если ответа нет в документах, он так и говорит.
- Качество ответов зависит от того, насколько документы полные и понятные.
